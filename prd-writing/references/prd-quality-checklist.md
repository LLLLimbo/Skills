# PRD Quality Checklist

## 1. 完整性检查

- [ ] 文档信息完整（版本、日期、状态、负责人）。
- [ ] 问题背景、目标、范围、边界明确。
- [ ] 需求来源有记录，并包含优先级（`P0/P1/P2`）。
- [ ] 每个功能模块均包含用户故事、交互、逻辑、异常、指标五部分。
- [ ] 包含通用规范、参考资料、更新日志。

## 2. 可验证性检查

- [ ] 验收标准均可观测、可测试。
- [ ] 每个关键需求至少对应一个验收标准。
- [ ] 指标包含目标值和观测方式（日志/埋点/报表/监控）。
- [ ] 非功能要求有明确验证方法。

## 3. 一致性检查

- [ ] 术语在全文中保持一致，无同义混用。
- [ ] 章节编号连续、层级正确。
- [ ] 优先级与目标一致（核心目标对应高优先级需求）。
- [ ] 交互流程与功能逻辑不冲突。
- [ ] 错误处理与权限规则不冲突。

## 4. 可执行性检查

- [ ] 需求描述聚焦 "做什么/为什么"，无过度实现细节。
- [ ] 上下游依赖、前置条件、约束条件已明确。
- [ ] 风险与边界场景已覆盖（异常、超时、权限、并发等）。
- [ ] 未知项已列入 "Open Questions"。

## 5. 中立性检查

- [ ] 文档不绑定特定业务背景（除非用户明确指定）。
- [ ] 文档不绑定特定技术栈（除非用户明确指定）。
- [ ] 未臆造用户数据、市场数据、法规数据。

## 6. 交付前门禁

仅当以下条件同时满足才视为可交付：

1. 完整性检查通过率 = 100%
2. 可验证性检查通过率 >= 90%
3. 一致性检查通过率 >= 90%
4. 可执行性检查通过率 >= 90%
5. 中立性检查通过率 = 100%
